## Verdicts

### 01-taint-crossfile

**Cross-process and cross-file taint propagation works, and findings are attributed to the caller's parameter.** Values traverse ~9 methods across 6 files and reach the sink. Every case passes, including the sink-side shapes the DFA engine has no pattern for -- those are caught by `ast-style-info-exposure-querystring` (CWE-89), which is why the harness must match on an explicit rule list rather than a rule-prefix blacklist (R1102).

Outstanding: 
- none

Known limitations: 
- none

### 02-domain-sensitive

**Range and guard narrowing is sound, including across call boundaries.** Local guards, `Math.min`/`Math.max` clamps, and the early-return idiom (`if (d == 0) return 0;`) are all honoured. The early-return case needed a false-edge fact the guard tracker could not express: the guard is popped by the JUMP that skips the else block, so the else body looked unguarded (R1101).

Outstanding: 
- none

Known limitations: 
- none

### 03-pointer-multilevel

**Field-, array- and container-sensitive aliasing is sound, and its guard transfer is sound with it.** Allocation-site identity, field sensitivity, per-key container cells, cross-method returns and call-site context all resolve; every alias precision gate (12 TN) holds. R1113 found the one way guard transfer was still unsound: the rule suppressed a finding whenever *some* alias was guarded, but the alias map is a may-relation, so a guard on `first` silenced a dereference of a `List.get` result that could equally be an unguarded `second`. It now requires the guard to cover the receiver's whole points-to set. R1114 added the null direction to the heap facts -- as a separate channel rather than a null sentinel, because one shared sentinel would make every null in the program compare equal and leak into the guard test -- which closes the `x.f = null` gap the fact domain previously could not express. One limit remains recorded: the AST rule cannot follow an alias at all.

Outstanding: 
- none

Known limitations: 
- `L6-AST-cannot-follow-the-alias`

### 04-polymorphic-callgraph

**Dispatch is sound and type-precise.** Interface / abstract / diamond hierarchies resolve; overloads are filtered by parameter type, so an `int` argument no longer binds to a `String` overload, and an arity-2 overload in the same class resolves on its own key.

Outstanding: 
- none

Known limitations: 
- none

### 05-real-cve-derived

**CWE-502 and CWE-117 are both fully supported.** All four deserialization shapes fire and both mitigations stay silent; all five Log4Shell shapes fire, including the three-frame cross-method case. The CWE-117 support needed two fixes: the `log.sinks` family had no checker bound to it at all, and a logger held in a static field lowered to the callee signature `LOG.info/1` with no type, so no FQN-anchored sink pattern could match. R1115 closed the third: an identifier allowlist is the only correct fix for ORDER BY / table / column, because bind variables cannot bind identifiers, and the engine modelled sanitizers purely by callee signature -- an allowlist is not a call, it is a value being narrowed. It is now recognised, and only in the reject-and-assign form: `if (!"a".equals(x)) { x = "a"; }` closes every path that could carry an unlisted value, while `if ("a".equals(x)) { x = "a"; }` does not, because its fall-through keeps the user's value. Every case now passes: 15/15 TP and 5/5 TN, with no false negatives. R1116 closed the last one by fixing the FIXTURE rather than the engine -- `runCommand` had been a `println` stand-in, so no `command.sinks` pattern could ever match and the case asserted a finding on a shape the engine has no sink for. Behind an `if (false)` guard it is inert at runtime and present in the IR, which is what a fixture is for. One case is recorded as a known limitation rather than counted: `LOG4SHELL-sanitized-tn`, where the real fix is a runtime configuration cutoff.

Outstanding: 
- none

Known limitations: 
- `LOG4SHELL-sanitized-tn`
