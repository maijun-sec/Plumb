**Range and guard narrowing is sound, including across call boundaries.** Local guards, `Math.min`/`Math.max` clamps, and the early-return idiom (`if (d == 0) return 0;`) are all honoured. The early-return case needed a false-edge fact the guard tracker could not express: the guard is popped by the JUMP that skips the else block, so the else body looked unguarded (R1101).

**R1201 extended that to the DISJUNCTION form.** `if (index < 0 || index > 2) { return null; }` is the same idiom with two comparisons, and it was NOT honoured: the guarded array access was reported by both the range rule and the taint heuristic. The reason is structural. A disjunction's TRUE edge proves nothing -- a disjunction being true implies only that ONE arm is true, so the tracker kept only the guards BOTH arms establish, and for two unrelated bounds that intersection is empty. The fact lives on the FALSE edge, where De Morgan applies: `!(a || b)` is `!a && !b`. The tracker now records the negated bounds of every arm against the branch's false target, and the range queries read that table. The upper bound needed one more fact: it was expressed against a LITERAL (`index <= 2`) rather than against `arr.length`, so the tracker now remembers the length of an array allocated with a literal size (`new String[3]`) and can transfer the bound to it.

**The false positive was invisible because the manifest's pin was off by one.** The case was pinned at line 22 -- the `return null` inside the guard -- while the engine reports the ARRAY LOAD at line 23, and the harness matches file+line EXACTLY. So the case could not see the finding and was measuring nothing, and the support matrix said "Outstanding: none" for a category that had a live false positive. The pin is now on the array load, like every other case in the category, and the case actually measures what it claims.
