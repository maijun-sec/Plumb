<a name="FB.AM_CREATES_EMPTY_JAR_FILE_ENTRY"/>
<span style="font-size:1.4em;font-weight:bold;">FB.AM_CREATES_EMPTY_JAR_FILE_ENTRY</span>
<table border=0 width="100%">
<tr><td width="40%" bgcolor="B0B0B0">SpotBugs: Bad practice</td><td bgcolor="B0B0B0">AM: API misuse</td><td bgcolor="B0B0B0"><a href="http://cwe.mitre.org/data/definitions/227.html">CWE-227</a></td></tr></table>
<p>The code calls <code>putNextEntry()</code>, immediately
followed by a call to <code>closeEntry()</code>. This results
in an empty JarFile entry. The contents of the entry
should be written to the JarFile between the calls to
<code>putNextEntry()</code> and
<code>closeEntry()</code>.</p>

<span style="font-size:1.4em;font-weight:bold;">FB.BAC_BAD_APPLET_CONSTRUCTOR</span>
<table border=0 width="100%">
<tr><td width="40%" bgcolor="B0B0B0">SpotBugs: Correctness</td><td bgcolor="B0B0B0">BAC: Bad Applet Constructor</td></tr></table>
<p>
This constructor calls methods in the parent Applet that rely on the AppletStub. Since the AppletStub
isn't initialized until the init() method of this applet is called, these methods will not perform
correctly.
