# R226 R209 DEBUG Print Static Flag Gate (2026-08-08)

## 背景

R209 (cross-method field chain) 在 `TaintAnalysis.java` 和 `TaintFact.java` 中加了 4 个 `System.err.println` 用于定位 TacVar identity 问题。这些 print 之前是 unguarded，每次 `badSink`/`goodSink`/`goodB2G` 调用都打：

- `TaintAnalysis.java:346-349` `[R209-DEBUG-CALL]` — `transferImpl` 入口
- `TaintAnalysis.java:842-845` `[R209-DEBUG-PRE-MW]` — 解析 callee 后
- `TaintAnalysis.java:879-883` `[R209-DEBUG-MW]` — merged walk 后
- `TaintFact.java:134-135` `[R209-DEBUG-FB]` — fieldMap fallback

每个 CWE sub 都有 ~600 个 badSink 调用 × 数十万次 `transferImpl` 调用 → stderr 巨量输出 + 阻塞 IO 严重影响性能。

## 修复

加 `private static final boolean R209_DEBUG = Boolean.getBoolean("plumb.r209.debug");` 静态 flag，所有 DEBUG print 改成 `if (R209_DEBUG) ...`。

通过 JVM flag `-Dplumb.r209.debug=true` 临时开启，默认 false。

**关键 diff** (TaintAnalysis.java ~line 63):
```java
private static final int MAX_RECURSION_DEPTH = 50;
private int currentDepth;
// R226: gate R209 DEBUG stderr prints (set to true only for diagnostic runs)
private static final boolean R209_DEBUG = Boolean.getBoolean("plumb.r209.debug");
```

**关键 diff** (TaintFact.java ~line 36):
```java
private static final TaintFact BOTTOM = new TaintFact(Map.of(), Map.of(), Map.of());

// R226: gate R209 DEBUG stderr prints (set to true only for diagnostic runs)
private static final boolean R209_DEBUG = Boolean.getBoolean("plumb.r209.debug");
```
