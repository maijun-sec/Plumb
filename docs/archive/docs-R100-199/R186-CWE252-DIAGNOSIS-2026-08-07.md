# R186 CWE-252 Unchecked Return Value — Diagnosis

**Date:** 2026-08-07
**Scope:** CWE-252 Unchecked Return Value — `FileInputStream.read()` return value discarded
**Status:** DIAGNOSIS (no fix landed, deferred)

## Current state (R182)

- CWE-252 score: 5.9% (1 TP / 17 bad files)
- Only 1 file fires (`CWE252_..._FileInputStream_01.java`)
- 16 of 17 bad files do NOT fire

## What the CWE-252 pattern looks like

All 17 bad files use the same sub-pattern (`FileInputStream.read()`):

```java
// bad()
streamFileInput.read(byteArray);          // return value discarded — CWE-252

// good1()
int numberOfBytesRead = streamFileInput.read(byteArray);
if (numberOfBytesRead == -1) { ... }      // return value checked
```

The 17 flow variants are:
- `_01`: baseline
- `_02`–`_17`: `if (true/false)` switches, dead-code patterns, scope modifications, etc.

## Why only _01 fires

The `UncheckedReturnCheck` requires:
1. `ins.kind == CALL` ✓
2. `ins.dest instanceof TacOperand.TacVar && dest.isTemp()` ✓ (the temp holds the return value)
3. `methodName == "read"` ✓
4. `ins.args.get(0) instanceof TacOperand.TacVar receiver` — receiver is `streamFileInput`
5. `shortTypeName(receiver.type()) == "FileInputStream"` — receiver type matches
6. `!isTempReferencedLater(fn, i, dest.name())` — dest temp not used later

For _01, all 6 conditions are met. For _02-_17, the empirical evidence (16 of 16 not firing) suggests one of conditions 2-6 is failing.

### Most likely root cause

The `if (true) { ... }` and `if (false) { ... }` blocks in _02-_17 cause the TacBuilder to emit `if_merge_` / `after_break_` / `after_continue_` Phi nodes (per the R135-R140 round of fixes for loop-phi emission). These Phi nodes reference earlier temps in unexpected ways, which trips the `isTempReferencedLater` check (condition 6).

Specifically: a Phi node at the merge point of `if (true) { read() }` references the dest temp `t_t0` to merge the if-true value with the if-false value. The substring search in `isTempReferencedLater` finds the Phi and returns true, suppressing the finding.

## Diagnostic next steps

A targeted R186 fix would:

1. Add an option to `UncheckedReturnCheck` to ignore Phi instructions when searching for "temp referenced later" (a Phi reference doesn't count as a "use" in the CWE-252 sense).
2. Run CWE-252 and verify the +16 TP gain.

The change is small (10-20 lines in `UncheckedReturnCheck.isTempReferencedLater`) but needs to be tested for FP regression: are there any CWE-252 good() bodies where the discarded read is intentional (e.g. ignoring the return value because EOF doesn't matter)?

## Action

Defer R186. Move to R187 (CWE-193 off-by-one baseline) which has no data yet. The CWE-252 +16 TP is a smaller gain than the CWE-113 / CWE-134 follow-ups.
