## The 4 FP Bug Fixes (R572/R574/R575 are the wins)

### R568 — Sanitizer (parseInt/parseLong/etc)
- **Root cause**: `InputSourcePatterns` marked `Integer.parseInt` etc as input sources, so the dest of these calls was tainted even though the return is a primitive bounded to the type's domain
- **Fix**: `isSanitizer(calleeSig)` check in CALL case BEFORE `checkSinkAtCall`
- **Impact**: R10 baseline 7,188 → 6,576 (-612), CWE-789 1,548 → 936

### R572 — NullDerefChecker MOVE re-assign (THE biggest win)
- **Root cause 1**: MOVE propagation only handled `src in nullTainted → propagate to dest`. It didn't handle `src CLEAN → remove dest from nullTainted`. So `File f = null; f = File.createTempFile(...); f.delete();` falsely fired because `f` stayed in null map
- **Root cause 2**: "First instruction clear" ran AFTER the null-MOVE handler, so the first `s = null` was added then immediately cleared
- **Fix**: MOVE removes dest if src CLEAN; use `initFunction` instead of "first instruction" check
- **Impact**: 1,954 FPs removed across 6 CWE dirs (CWE-523/378/459/226/390/605)

### R574 — OmittedBreakInSwitch regex
- **Root cause**: `containsTerminator` used `\b...\b` regex, but after stripping whitespace the case body `return FFFF.clone();` becomes `returnFFFF.clone()`. The trailing `\b` after "return" fails because next char "F" is word char
- **Fix**: Use `s.contains("return")` instead of regex
- **Impact**: 151 FPs from `case X: return ...;` patterns

### R575 — SuspiciousComment marker list
- **Root cause**: "SECURITY" was a marker word. Javadocs that innocently mention "due to security restrictions" triggered the rule
- **Fix**: Marker list uses colon-suffix forms (SECURITY: / TODO: / TBD:). Bare SECURITY/TODO/TBD no longer match
- **Impact**: 141 FPs removed

## Key Lessons (cross-project)

1. **Real-codebase validation is essential** — Juliet is controlled; real code has license/copyright/Javadoc/boilerplate noise. R573 was the breakthrough that surfaced 4 FP bugs.

2. **Per-rule per-dir breakdown is the FP discovery pattern**:
   - R570 (full sweep) → R571 (high-fire investigation) → R572/R574/R575 (fixes)
   - Pattern: when a rule fires disproportionately on a dir, drill down

3. **Common FP bug patterns**:
   - **MOVE re-assign without clear**: state stays across reassign
   - **initFunction vs first-instruction clear**: ordering issues
   - **Regex `\b...\b` after whitespace strip**: word boundary fails
   - **Marker word too common**: "SECURITY" / "TODO" in Javadoc

4. **R10 baseline is NOT sufficient for FP measurement**:
   - R10 baseline: 6,576 fires (Juliet, controlled) — R572/R574/R575 didn't change this
   - Real-codebase: 586 fires in 326 files (~70% FP)
   - You need BOTH to know the real picture

5. **Single-CWE-distribution R5XX pattern works**:
   - 5-15 sec per CWE dir vs R520's 5+ min full sweep
   - Standard for new CWE family validation

6. **Cross-fn gap is the biggest remaining TP ceiling**:
   - R567 FN cases (2) all need R5+ cross-fn summary-fold
   - 126 CWE-259 + 23 CWE-256 cross-TU gap
   - 5-day project, design done in R577
