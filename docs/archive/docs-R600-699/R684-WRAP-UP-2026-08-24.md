## 2. 关键决策

| 决策 | 选项 | 理由 |
| --- | --- | --- |
| 打包形态 | Shaded uber-jar + 捆绑 JRE (jlink) | 用户机器**零 Java 依赖** |
| API Key 优先级 | env > YAML > 内置 default | 双通道,env 优先 (R684 用户选择) |
| 模板外置 | README/CHANGELOG 在 `scripts/templates/*.template` | 解决 PowerShell 5.1 ANSI 解析中文 here-string 问题 |
| JRE 缺失 graceful | `--no-jlink` flag + 清晰错误提示 | jmods 不在 PATH 时不阻断 |
| 启动器 | `bin/plumb` (POSIX) + `bin/plumb.bat` (Windows) | 双平台,自动检测捆绑 jre → $JAVA_HOME → PATH |
| 文档语言 | 中文为主,关键术语英文 | 与现有 `doc/usage/CLI.md` 一致 |

## 3. PowerShell 5.1 中文 here-string 踩坑 (R684-NEW)

**问题**:PowerShell 5.1 默认按 ANSI (GBK) 读 UTF-8 无 BOM 文件,中文乱码 → here-string `"@` 闭合错位 → parser 报"The string is missing the terminator: `"@`"。

**修复**:把 README/CHANGELOG 模板**外置**为 `scripts/templates/*.template` (UTF-8 无 BOM),脚本用 `Get-Content -Encoding UTF8` 读 + `-replace` 注入变量。**不依赖 BOM**(会影响其他工具)。

**影响**:dist-jlink-linux.sh 也对齐了模板方式(用 `sed` 注入变量),跨平台一致。

**另一个坑**:`& java.exe -version` 写 stderr,PowerShell 5.1 把 stderr 当 native-command error。修复:用 `cmd /c "java -version 2>&1"` 包装,或把 `2>&1` 显式重定向到变量后再 `Write-Host`。
