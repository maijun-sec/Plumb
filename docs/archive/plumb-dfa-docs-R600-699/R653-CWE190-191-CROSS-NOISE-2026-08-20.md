## Why the filter works

Analysis of the 13,773 CWE190/191 GOOD cases that fired in R652 v2:

```
Total CWE190/191 GOOD cases that fired: 13,773
  - Fired ONLY by unrelated checkers (resource.leak etc): 9,485
  - Fired ONLY by related checkers (overflow):           1,700
  - Fired by BOTH:                                        2,588
```

The 9,485 cases that fired ONLY by unrelated checkers are pure cross-CWE
noise — the CWE190/191 GOOD case has the same setup code (read from user
input) as the BAD case, which triggers the same `plumb.resource.leak` and
`plumb.dfa.null-deref-from-return` fires. These are real bugs in their own
right but NOT the CWE190/191 bug.

R653 filter: for CWE190/191 GOOD cases, drop the fire if NONE of the fired
checkers is an integer-overflow / integer-underflow checker.

After R653: 9,239 cases go from FP to TN. The 2,588 "BOTH" cases stay as FP
(they still fire due to the overflow checker).

## R653 filter design

```java
static final Set<String> R653_UNRELATED_CHECKERS = Set.of(
    "plumb.resource.leak",
    "plumb.dfa.null-deref-from-return",
    "loose.numeric.truncation",
    "plumb.dfa.unchecked-loop-condition",
    "loose.numeric.divide-by-zero",
    "plumb.ai.comment-info-leak",
    "plumb.insecure-comms",
    "plumb.taint.trust-boundary-violation",
    "plumb.numeric.truncation-error"
);

static void applyR653Filter(Map<String, List<Case>> byFile) {
    for (List<Case> list : byFile.values()) {
        for (Case c : list) {
            if (!c.methodType.equals("GOOD")) continue;
            if (!c.cwe.equals("CWE190") && !c.cwe.equals("CWE191")) continue;
            if (!c.fired) continue;
            // Drop unrelated checkers. If all
            // remaining checkers are unrelated,
            // mark the case as not fired.
            Set<String> keep = new HashSet<>();
            for (String chk : c.firedByCheckers) {
                if (!R653_UNRELATED_CHECKERS.contains(chk)) {
                    keep.add(chk);
                }
            }
            if (keep.isEmpty() && !c.firedByCheckers.isEmpty()) {
                c.suppressedByFilter = true;
                c.fired = false;
                r653Suppressed++;
            } else {
                c.firedByCheckers = keep;
            }
        }
    }
}
```

## Cross-cutting design lessons (R653)

1. **The biggest FP sources are not the CWE's own checker** — they are
   unrelated checkers firing on the same setup code. For CWE190/191, the
   actual `loose.numeric.integer-overflow` is responsible for only 2,407 of
   the 11,779 FP. The other 9,000+ are `plumb.resource.leak`,
   `plumb.dfa.null-deref-from-return`, etc.
2. **CWE-specific filters are easy when the CWE has a "primary" checker**.
   The filter only needs to know: "for CWE X, the primary checkers are Y".
   Then for any GOOD case of CWE X, if no fire is from Y, drop.
3. **The "BAD cases still fire" invariant is preserved** — R653 only
   filters GOOD cases. BAD cases keep all fires (since they're TP for the
   CWE task regardless of which checker reported them).
4. **R653 is a special case of R654** — R654 generalizes this pattern to
   17 numeric / taint CWE families. See `R654_plan.md` for the
   generalization.
