## Per-round deep dive

### R10 Track 1 — ProcessControlChecker (CWE-114)

**Why DFA, not taint**: Existing `jni.sinks` family is
taint — only fires when `loadLibrary` arg is tainted.
But CWE-114 is the API choice itself: `loadLibrary`
lets JVM search standard library paths
(LD_LIBRARY_PATH / java.library.path). Even with
literal `"test.dll"`, an attacker who controls
LD_LIBRARY_PATH can hijack the load. Taint cannot
see this — only structural pattern matching can.

**Pattern**: fire on `System.loadLibrary/1` /
`Runtime.loadLibrary/1` (both FQN + short forms).
**Not** fire on `System.load/1` (the FIX pattern —
explicit full path, no JVM search).

**R520 sweep**: 17/17 CWE-114 hits, 6092ms.

**WARNING**: my original R10 implementation was
silently overwritten by an R16 "literal-tracking"
version mid-session. The user-facing API
(`plumb.dfa.process-control`, CWE-114) is identical,
so test failures were the only signal. I restored
R10 design. Future R-rounds should be careful:
another agent/tool may overwrite files.

### R10 Track 2 — UncheckedReturnChecker R10-A bug fix

**The latent bug**: `isFailable(String calleeSig)`
parser used `#` to split method/class, but TAC IR
has TWO callee sig formats:
- **Java source**: `java.io.File.delete/0` (FQN.method/arity)
- **Jimple bytecode**: `java.io.File#delete/0` (FQN#method/arity)

`JimpleToTacConverter.java:590` uses `#`;
`ExpressionTranslator.java:333` uses `.`. The `#` parser
only matched Jimple output — Java source IR (the
vast majority of plumb-dfa use cases) was
effectively never matched. The `FAILABLE` map was
effectively **dead code** for the primary code path.

**The fix**: detect format by sig content: if `#` is
present, use `#`; else use `.`.

**New FAILABLE entries**:
- `read` (InputStream/Reader) — unlocks CWE-252
- `readLine` (BufferedReader)
- `remove` (Collection/Map subtypes)

**R520 sweep**: 66 fires in 17 files (3.9 hits/file),
284850ms.

**Lesson**: 5+ year old dead code always passed
unit tests because tests themselves used `#` format.
Real Juliet is Java source, so it never fired. After
R10 fix went 0 → 66 fires. **Every static analysis
rule must run on real corpus; unit tests alone
are not enough.**

**3 other checkers** with same `#` bug:
`OrmLoadNullCheckDfaChecker`, `OrmUnnecessaryGetDfaChecker`,
`ServletAtomicityDfaChecker` — deferred to R10-A2
(ORM/servlet specific, low priority).

### R11 — NullDerefChecker extension (CWE-690)

**3 changes**:
1. **Separate `nullTaintedVars` map** — DO NOT reuse
   base class's `taintedVars` (which marks every
   param as "untrusted source", would cause massive
   FPs).
2. **"May return null" heuristic** — if CALL
   callee name contains "Bad" / "Null" / etc.,
   mark dest as null-tainted.
3. **CALL receiver check** — R6-A convention: CALL
   receiver is at `args[0]`, not `lhs1`. CWE label
   is CWE-690 for CALL, CWE-476 for FIELD/ARRAY.

**R547 sweep**: **735 fires in 488 files / 8.4 sec**
(was 0 before R11). a_hit 102 / b_hit 69 / good_hit 0
— no FPs on good variants.

**Lesson #2 (cross-project)**: separate taint maps
for distinct domains. R11 critical lesson:
NullDerefChecker needed its own `nullTaintedVars`
map, NOT reuse TaintedCheckerBase's `taintedVars`
(which marks every param as "untrusted source").
The two domains are conceptually similar but
operationally different.

### R12 — ResourceExhaustionChecker (CWE-400 sleep)

**Pattern**: track taint (readLine/parseInt/getParameter),
fire on `Thread.sleep/1` with tainted arg.
**Sibling of R9 UncheckedLoopConditionChecker**: same
taint tracking, different sink (Thread.sleep vs
for-loop bound).

**R546 sweep**: 510 sleep fires + 1326 sibling
CWE-606 (for_loop/write) = **1836 total in 135s** on
2,396 files. CWE-400 sleep is the right label for
sleep (resource consumption, not loop condition).

### R13 — MissingCryptoInitChecker (CWE-325)

**Pattern**: track KeyGenerator / KeyPairGenerator
/ MessageDigest instances. Mark dest's TYPE as
"needs init" after `getInstance`. Mark as
"initialized" after `init()` / `update()` / `initialize()`.
Fire on `generateKey()` / `digest()` / `generateKeyPair()`
if not initialized.

**TAC IR quirk**: dest of factory is `t_t1:KeyGenerator`
(FQN), but `generateKey/0` args[0] is
`keyGenerator:KeyGenerator` (short). Same TYPE, different
name. Solved by tracking per-TYPE.

**R548 sweep**: 34/34 hits (100%), 2181ms.

**R10-A2** and **R13** share the type-based tracking
pattern: TAC IR drops source-var names, so tracking
by name misses cross-temp references. Track by TYPE
instead.

### R14 — CatchGenericExceptionChecker (CWE-396)

**Pattern**: fire on CATCH_HANDLER whose `ctorType` is
`Exception` / `Throwable` / `Error` (RuntimeException
intentionally excluded — common legitimate catch).

**R549 sweep**: 34/34 hits (100%), 2351ms.

**R520 sweep with 30+ checkers**: 100 findings total —
34 CWE-396 + 60 CWE-248 (UncaughtExceptionPropagator
also fires on same files) + 6 CWE-484 (false positives
on switch in catch).

### R15 — InsecureCookieChecker (CWE-614)

**Pattern**: track Cookie instances. Mark TYPE as
"needs setSecure" after `new Cookie(...)`. Mark as
secure after `setSecure(true)`. Fire on `addCookie(cookie)`
if not secure.

**TAC IR quirk #2**: `new Cookie(...)` is a NEW
instruction (not CALL). `addCookie/1` args[0] is the
response receiver, args[1] is the cookie. Type-based
tracking (R13 lesson applied).

**R550 sweep**: 17/17 hits (100%), 1450ms.

### R16 — ThrowGenericExceptionChecker (CWE-397)

**Pattern**: fire on NEW instruction whose ctorType
is `Exception` / `Throwable` / `Error` / `RuntimeException`.

**R551 sweep**: 2/4 hits. The 2 missing are
`declare_Exception` / `declare_Throwable` — these
are AST-level (method signature `throws Exception`
vs `throw new Exception()`). Defer to AST-level
analyzer.

## Cross-cutting lessons (cross-project applicable)

1. **TAC IR has TWO callee sig formats** — Java source `.`,
   Jimple `#`. Any checker parser must detect format first.
2. **TAC dest ≠ CALL args[0] receiver** — R6-A: receiver
   is at `args[0]`, dest is the return value.
3. **NEW vs CALL** — constructors use NEW instruction
   with `ctorType` field, not CALL with `calleeSig`.
4. **TAC IR drops source-var names** — track by TYPE
   not by TacVar object identity.
5. **Separate taint maps for distinct domains** — R11
   critical: don't reuse base class's `taintedVars`
   for "may-be-null" domain.
6. **Always re-read file after writing** — my R10
   ProcessControlChecker was overwritten by an R16
   version mid-session.
7. **Single-checker sweep pattern (R54X)** — for new
   CWE families: load 1-2 checkers, run on CWE dir,
   5-15 sec per CWE vs R520's 5+ min with 30+ checkers.
8. **Sibling-checker pattern** — when two CWE families
   share taint logic but different sinks, write
   sibling checkers that share taint tracking but
   fire on different sinks.
